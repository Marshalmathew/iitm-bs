\chapter{Logarithmic Functions and Information Metrics}
\index{Logarithms}

Logarithmic functions are the formal mathematical inverses of exponential operations. While exponential growth rapidly expands numerical values toward infinity, logarithms compress immense dynamic ranges into manageable linear scales. In data science, machine learning, and information theory, logarithms play an indispensable role: they prevent arithmetic underflow when multiplying microscopic probabilities, define Maximum Likelihood Estimation (MLE) objectives, formulate Cross-Entropy loss in neural networks, and quantify information entropy in decision trees.

\section{Definition of Logarithmic Functions}

\begin{intuitionbox}{Un-growing Exponential Growth}
If exponentials answer "what do I get if I double a number 10 times?", logarithms answer the reverse: "how many times do I need to halve this number to get back to 1?". They measure the magnitude of scale, which is why the Richter scale (for earthquakes) or Decibels (for sound) use logarithms to compress huge energy differences into small numbers like 6.0 or 7.0.
\end{intuitionbox}

\begin{definitionbox}{Logarithmic Function}
For $a > 0$ and $a \neq 1$, the logarithmic function with base $a$, denoted $\log_a(x)$, is defined as the inverse of the exponential function $y = a^x$:
$$y = \log_a(x) \iff a^y = x \quad (\text{for } x > 0)$$
\begin{itemize}
    \item \index{Domain}\textbf{Domain:} $(0, \infty)$ (you cannot take the log of a negative number or zero).
    \item \index{Range}\textbf{Range:} $(-\infty, \infty)$ (can output any real number).
    \item \textbf{Vertical Asymptote:} The line $x = 0$ (y-axis) is a vertical asymptote because as $x \to 0^+$, $y \to -\infty$ (for $a > 1$).
    \item \index{Natural Logarithm}\textbf{Natural Logarithm:} The log with base $e$:
    $$\ln(x) = \log_e(x)$$
    \item \index{Common Logarithm}\textbf{Common Logarithm:} The log with base $10$:
    $$\log(x) = \log_{10}(x)$$
\end{itemize}
\end{definitionbox}

\textbf{Data Science Relevance:} In data preprocessing, if a dataset has a heavily right-skewed distribution (like income data where a few billionaires warp the scale), applying a \index{Log Transformation}\textbf{Log Transformation} ($y = \log(x)$) compresses the massive outliers and expands the smaller values, often resulting in a more normal, bell-shaped distribution that machine learning models prefer.

\begin{lstlisting}[language=Python, caption=Data Science: Log Transformation in Python]
import numpy as np

# Highly skewed income data
incomes = np.array([30000, 45000, 1000000, 50000, 2500000])

# Apply Natural Log transformation to compress outliers
log_incomes = np.log(incomes)
print("Original:", incomes)
print("Log transformed:", np.round(log_incomes, 2))
\end{lstlisting}

\section{Laws of Logarithms}
\index{Laws of Logarithms}

Because logarithms are essentially exponents, they follow algebraic rules derived directly from the laws of exponents. These rules are computationally powerful because they turn multiplication into addition, which computers can process much faster and with less risk of numerical overflow.

\begin{theorembox}{Laws of Logarithms}
For any positive numbers $x, y$, base $a > 0, a \neq 1$, and real number $p$:
\begin{itemize}
    \item \textbf{Product Rule:} $\log_a(xy) = \log_a(x) + \log_a(y)$
    \item \textbf{Quotient Rule:} $\log_a\left(\frac{x}{y}\right) = \log_a(x) - \log_a(y)$
    \item \textbf{Power Rule:} $\log_a(x^p) = p \log_a(x)$
    \item \textbf{Base Identity:} $\log_a(a) = 1$ and $\log_a(1) = 0$
    \item \textbf{Inverse Properties:} $\log_a(a^x) = x$ and $a^{\log_a(x)} = x$
    \item \textbf{Change of Base Formula:} For any new positive base $b$:
    $$\log_a(x) = \frac{\log_b(x)}{\log_b(a)} = \frac{\ln(x)}{\ln(a)}$$
\end{itemize}
\end{theorembox}

\begin{examplebox}{Simplifying Logarithmic Expressions}
Simplify the expression: $3\ln(x) + \frac{1}{2}\ln(y) - 2\ln(z)$ into a single logarithm.
\begin{enumerate}
    \item Apply the power rule first to move the coefficients into the exponents:
    $$\ln(x^3) + \ln(y^{1/2}) - \ln(z^2)$$
    \item Apply the product rule to combine the first two terms being added:
    $$\ln(x^3 \cdot \sqrt{y}) - \ln(z^2)$$
    \item Apply the quotient rule to incorporate the subtracted term:
    $$\ln\left(\frac{x^3\sqrt{y}}{z^2}\right)$$
\end{enumerate}
\end{examplebox}

\section{Solving Equations}

We use the inverse relationship between exponentials and logarithms to isolate variables that are trapped inside exponents or log functions.

\subsection{Solving Exponential Equations}
When the variable is in the exponent, we take the logarithm of both sides to bring the variable down.

\begin{examplebox}{Solving Exponential Equations}
Solve the equation: $5^{2x-1} = 3^x$.
\begin{enumerate}
    \item Take the natural logarithm ($\ln$) of both sides:
    $$\ln(5^{2x-1}) = \ln(3^x)$$
    \item Apply the power rule to bring down the exponents:
    $$(2x - 1)\ln(5) = x\ln(3)$$
    \item Expand the left side:
    $$2x\ln(5) - \ln(5) = x\ln(3)$$
    \item Gather all terms containing $x$ on one side:
    $$2x\ln(5) - x\ln(3) = \ln(5)$$
    \item Factor out $x$:
    $$x(2\ln(5) - \ln(3)) = \ln(5)$$
    \item Solve for $x$:
    $$x = \frac{\ln(5)}{2\ln(5) - \ln(3)} = \frac{\ln(5)}{\ln(25) - \ln(3)} = \frac{\ln(5)}{\ln(25/3)}$$
\end{enumerate}
\end{examplebox}

\subsection{Solving Logarithmic Equations}
When the variable is inside a logarithm, we isolate the logarithm and then rewrite the equation in its exponential form.

\begin{examplebox}{Solving Logarithmic Equations}
Solve the equation: $\log_2(x) + \log_2(x-2) = 3$.
\begin{enumerate}
    \item Combine the logarithms using the product rule:
    $$\log_2(x(x-2)) = 3 \implies \log_2(x^2 - 2x) = 3$$
    \item Convert to exponential form to eliminate the log:
    $$x^2 - 2x = 2^3 \implies x^2 - 2x = 8$$
    \item Move terms to one side to form a standard quadratic equation:
    $$x^2 - 2x - 8 = 0 \implies (x-4)(x+2) = 0$$
    So the potential solutions are $x = 4$ or $x = -2$.
    \item \index{Extraneous Solutions}\textbf{Check for extraneous solutions (Crucial!):}
    \begin{itemize}
        \item If $x = 4$: The original terms $\log_2(4)$ and $\log_2(2)$ are both evaluating positive numbers, which is valid.
        \item If $x = -2$: The original term $\log_2(-2)$ is undefined because the domain of logs is strictly positive. So $x=-2$ is an extraneous solution.
    \end{itemize}
\end{enumerate}
Thus, the only valid solution is $x = 4$.
\end{examplebox}

\section{Common Pitfalls, Traps \& Misconceptions}

\begin{trapbox}{Trap 1: The Log-of-Sum Linear Fallacy}
A shockingly frequent algebra blunder is distributing logarithms across sums:
$$\log_a(x + y) \neq \log_a(x) + \log_a(y)$$
\begin{itemize}
    \item \textbf{The True Rule:} Logarithms convert \textbf{products} into sums: $\log_a(x \cdot y) = \log_a(x) + \log_a(y)$.
    \item The expression $\log_a(x + y)$ cannot be expanded algebraically; it must remain as is.
    \item Similarly, $\frac{\log_a(x)}{\log_a(y)} \neq \log_a(x - y)$. Rather, $\frac{\log_a(x)}{\log_a(y)} = \log_y(x)$ (Change of Base).
\end{itemize}
\end{trapbox}

\begin{trapbox}{Trap 2: Extraneous Roots from Product Compression}
When solving logarithmic equations, combining logs via the product rule can accidentally create illegal, ghost solutions.
\begin{itemize}
    \item Consider $\log_2(x) + \log_2(x - 2) = 3$. Combining yields $\log_2(x(x - 2)) = 3 \implies x^2 - 2x - 8 = 0$, giving $x = 4$ and $x = -2$.
    \item Notice that in the merged equation $\log_2(x(x - 2))$, plugging in $x = -2$ produces $(-2)(-4) = +8 > 0$, so $\log_2(8) = 3$ appears valid!
    \item But in the \textbf{original} uncombined equation, $\log_2(-2)$ is mathematically undefined!
    \item \textbf{Golden Rule:} You must \textbf{always} check solutions in the original, un-simplified logarithmic equation!
\end{itemize}
\end{trapbox}

\begin{trapbox}{Trap 3: The Power Rule Domain Alteration Trap}
Students often assume that $\ln(x^2)$ and $2\ln(x)$ are identically equal functions.
\begin{itemize}
    \item $\ln(x^2)$ requires only $x^2 > 0$, so its natural domain is $\mathbb{R} \setminus \{0\}$ (all non-zero numbers, including negatives: $\ln((-3)^2) = \ln(9)$).
    \item $2\ln(x)$ requires $x > 0$ strictly, so its domain is $(0, \infty)$.
    \item The true rigorous algebraic identity is: $\ln(x^2) = 2\ln(|x|)$. Omitting the absolute value truncates half of the function's domain.
\end{itemize}
\end{trapbox}

\begin{trapbox}{Trap 4: Probability Products vs. Floating-Point Underflow}
In machine learning (e.g. Naive Bayes, Hidden Markov Models, Language Modeling), we compute the likelihood of $N$ data points:
$$L(\theta) = \prod_{i=1}^N P(x_i \mid \theta)$$
\begin{itemize}
    \item Because probabilities satisfy $0 \le P(x_i) < 1$, multiplying hundreds of probabilities causes the product to exponentially decay: $0.01^{100} = 10^{-200}$.
    \item Standard 64-bit IEEE floating-point numbers underflow to exact zero ($0.0$) below $\approx 10^{-308}$, destroying gradient calculations and crashing training loops.
    \item Taking the natural logarithm converts the tiny product into a numerically robust negative sum:
    $$\ln L(\theta) = \sum_{i=1}^N \ln P(x_i \mid \theta)$$
    Log-likelihood avoids numerical underflow and makes optimization strictly linear!
\end{itemize}
\end{trapbox}

\section{Python Implementation: Probability Underflow, Cross-Entropy, and Log-Sum-Exp}

\begin{lstlisting}[caption={Numerical Stability, Cross-Entropy Loss, and Logarithms in Python}]
import numpy as np

# 1. Floating-Point Underflow Simulation
# Multiplying 100 small probabilities directly vs. summing log-probabilities
probs = np.full(100, 0.001)

direct_product = np.prod(probs)
print(f"Direct Product of 100 probabilities: {direct_product}")
# Underflows to 0.0!

# Log-likelihood representation:
log_sum = np.sum(np.log(probs))
print(f"Log-Likelihood Sum:                 {log_sum:.4f}")
print(f"Numerical Underflow completely prevented!\n")

# 2. Binary Cross-Entropy Loss Function Implementation
# L(y, p) = - [ y * ln(p) + (1 - y) * ln(1 - p) ]
def binary_cross_entropy(y_true, y_pred, eps=1e-15):
    # Clip predictions to prevent ln(0) -> NaN
    y_pred_clipped = np.clip(y_pred, eps, 1.0 - eps)
    loss = - (y_true * np.log(y_pred_clipped) + (1.0 - y_true) * np.log(1.0 - y_pred_clipped))
    return np.mean(loss)

y_true = np.array([1, 0, 1, 1, 0])
y_pred_confident = np.array([0.95, 0.05, 0.90, 0.85, 0.10])
y_pred_poor      = np.array([0.10, 0.80, 0.20, 0.30, 0.90])

print(f"BCE Loss (Confident Model): {binary_cross_entropy(y_true, y_pred_confident):.4f}")
print(f"BCE Loss (Poor Model):      {binary_cross_entropy(y_true, y_pred_poor):.4f}")

# 3. Shannon Entropy: H(X) = - sum(p_i * log2(p_i))
def shannon_entropy(probabilities):
    p = np.array(probabilities)
    p = p[p > 0]  # By convention: 0 * log2(0) = 0
    return -np.sum(p * np.log2(p))

fair_coin = [0.5, 0.5]
biased_coin = [0.99, 0.01]
print(f"\nShannon Entropy of Fair Coin:   {shannon_entropy(fair_coin):.4f} bits (Max uncertainty)")
print(f"Shannon Entropy of Biased Coin: {shannon_entropy(biased_coin):.4f} bits (Near deterministic)")
\end{lstlisting}

\subsection*{Part B: Conceptual and Diagnostic Multiple Choice Questions}

\begin{enumerate}[resume]
\item \textbf{Conceptual Diagnostic: Extraneous Logarithmic Solutions} \\
A student attempts to solve the equation $\log_4(x) + \log_4(x - 3) = 1$. The student writes:
$$\log_4(x(x - 3)) = 1 \implies x^2 - 3x = 4 \implies x^2 - 3x - 4 = 0 \implies (x - 4)(x + 1) = 0$$
The student states that the solution set is $\{4, -1\}$. What is the \textbf{correct mathematical assessment}?
\begin{enumerate}
    \item The student is entirely correct; both roots satisfy the algebraic quadratic equation.
    \item The student is incorrect because $x = 4$ is extraneous; the only true root is $x = -1$.
    \item The student is incorrect because $x = -1$ is an extraneous root; substituting $x = -1$ into the original expression yields $\log_4(-1)$, which is undefined over the real numbers. The only valid solution is $x = 4$.
    \item The student is incorrect because base-4 logarithms require taking the fourth root of both sides.
\end{enumerate}

\item \textbf{Conceptual Diagnostic: Log-Likelihood vs. Numerical Underflow} \\
In training a generative Gaussian Mixture Model on 1,000 independent continuous data points, why do machine learning frameworks optimize the **log-likelihood** $\sum_{i=1}^{1000} \ln p(x_i \mid \theta)$ rather than the direct likelihood $\prod_{i=1}^{1000} p(x_i \mid \theta)$?
\begin{enumerate}
    \item Because taking the logarithm changes the location of the optimal parameter $\theta^*$.
    \item Because the direct product of 1,000 probabilities $\prod_{i=1}^{1000} p(x_i)$ decays exponentially to a magnitude far below $10^{-308}$, triggering catastrophic floating-point arithmetic underflow to $0.0$; the logarithm transforms tiny products into well-scaled sums without shifting the argmax.
    \item Because logarithms eliminate the need to compute derivatives during optimization.
    \item Because direct products cannot be evaluated on GPU hardware.
\end{enumerate}
\end{enumerate}
