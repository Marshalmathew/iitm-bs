\chapter{Loops, Iteration \& Convergence Algorithms}

Iteration is the engine of computational science. Whether training a deep neural network over millions of gradient updates, traversing sparse graph structures, or calculating Monte Carlo approximations, programs rely on repetitive execution constructs. In Python, iteration is elevated from primitive pointer manipulation to an expressive, protocol-driven architecture. Understanding how the \texttt{range} object generates arithmetic progressions in $O(1)$ space, how condition-driven \texttt{while} loops converge toward fixed points, and how the loop \texttt{else} construct guarantees invariant verification provides the groundwork for scalable scientific computing.

\section{Mathematical \& Computational Foundations}

\subsection{Loop Variants, Invariants, and Termination Proofs}

\begin{definitionbox}{Formal Loop Invariants and Variants}
\index{Loop Invariant} \index{Loop Variant}
A \textbf{loop invariant} is a mathematical predicate $I$ that holds true immediately before and immediately after every iteration of a loop.
A \textbf{loop variant} is an integer-valued function $V(s)$ of the program state $s$ satisfying two strict criteria:
\begin{enumerate}
    \item $V(s) \ge 0$ whenever the loop guard condition evaluates to \texttt{True}.
    \item $V(s)$ strictly decreases with each successive loop iteration: $V(s_{k+1}) < V(s_k)$.
\end{enumerate}
By the well-ordering principle of the non-negative integers, any loop possessing a valid variant function is mathematically guaranteed to terminate in at most $V(s_0)$ steps, proving the impossibility of an infinite loop.
\end{definitionbox}

\subsection{The \texttt{range} Arithmetic Sequence Object}

\begin{theorembox}{Space and Time Complexity of \texttt{range}}
\index{range Object}
In Python 3, \texttt{range(start, stop, step)} is not a list in memory; it is an \textbf{immutable sequence type} that represents an arithmetic progression:
\begin{equation}
r_k = \text{start} + k \times \text{step}, \quad \text{for } 0 \le k < \left\lceil \frac{\text{stop} - \text{start}}{\text{step}} \right\rceil
\end{equation}
The memory consumption of a \texttt{range} object is strictly $\mathcal{O}(1)$ regardless of the span between \texttt{start} and \texttt{stop}. A range representing a trillion numbers:
\begin{lstlisting}[language=Python]
import sys
r = range(0, 10**12, 2)
print(sys.getsizeof(r))  # Consumes only 48 bytes!
\end{lstlisting}
Furthermore, membership testing ($x \in r$) operates in $\mathcal{O}(1)$ time via direct arithmetic:
\begin{equation}
x \in r \iff \left( \frac{x - \text{start}}{\text{step}} \in \mathbb{Z}_{\ge 0} \right) \land (\text{start} \le x < \text{stop})
\end{equation}
\end{theorembox}

\subsection{Loop Control Algebra: \texttt{break}, \texttt{continue}, and Loop \texttt{else}}

\begin{theorembox}{Operational Semantics of the Loop \texttt{else} Clause}
\index{Loop else Clause}
Python features a distinctive syntactical construct: an \texttt{else} clause attached directly to a \texttt{for} or \texttt{while} statement:
\begin{lstlisting}[language=Python]
for item in collection:
    if target_condition(item):
        found = True
        break
else:
    # Executed ONLY if the loop completed without encountering 'break'
    handle_target_not_found()
\end{lstlisting}
The \texttt{else} block executes if and only if the loop terminates normally (either the sequence was exhausted in a \texttt{for} loop, or the loop guard condition became false in a \texttt{while} loop). If the loop is terminated prematurely by a \texttt{break} statement, the \texttt{else} block is entirely skipped.
\end{theorembox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Numerical Convergence Loops in Machine Learning}
Many machine learning algorithms (such as Logistic Regression, $k$-Means, and Gradient Descent) find optimal parameters $\theta$ by iteratively updating an initial estimate:
\begin{equation}
\theta_{k+1} = \theta_k - \eta \nabla L(\theta_k)
\end{equation}
where $\eta > 0$ is the learning rate and $\nabla L$ is the gradient of the loss function. In computational implementations, iteration stops when either:
\begin{enumerate}
    \item \textbf{Absolute convergence:} $\|\theta_{k+1} - \theta_k\| < \epsilon$, where $\epsilon$ is the convergence tolerance.
    \item \textbf{Resource exhaustion guard:} $k \ge \text{max\_iter}$ (preventing infinite loops when gradients oscillate or diverge).
\end{enumerate}

\subsection{Time Complexity of Nested Iteration}
When nesting loops, the total iterations scale multiplicatively:
\begin{equation}
T(N, M) = \sum_{i=1}^N \sum_{j=1}^M \mathcal{O}(1) = \mathcal{O}(N \times M)
\end{equation}
For quadratic problems ($M = N$), $T(N) = \mathcal{O}(N^2)$. For triangular patterns ($\sum_{i=1}^N i = \frac{N(N+1)}{2}$), the asymptotic complexity remains $\mathcal{O}(N^2)$. In large-scale data science, raw Python nested loops must be replaced by vectorized array operations to eliminate bytecode interpretation overhead.

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{Mutating a Sequence During Active Iteration}
Modifying a list while iterating over it with a \texttt{for} loop causes silent element skipping:
\begin{lstlisting}[language=Python]
numbers = [1, 2, 3, 4, 5, 6]
for num in numbers:
    if num % 2 == 0:
        numbers.remove(num)  # Modifying container during traversal!
print(numbers)  # Output: [1, 3, 5] -- wait, why did 4 get skipped?
\end{lstlisting}
Python tracks iteration using an internal integer index counter. When element \texttt{2} at index 1 is deleted, element \texttt{3} shifts left into index 1, and element \texttt{4} shifts into index 2. The next loop step advances the counter to index 2, pointing to \texttt{4}'s new position and completely skipping the examination of \texttt{3}! Always iterate over a copy (\texttt{for num in numbers[:]:}) or construct a new list via comprehension.
\end{trapbox}

\begin{trapbox}{Infinite Floating-Point \texttt{while} Loops}
Using exact equality comparisons in floating-point iteration guards causes infinite loops:
\begin{lstlisting}[language=Python]
x = 0.0
while x != 1.0:  # INFINITE LOOP!
    x += 0.1
\end{lstlisting}
Because $0.1$ is a repeating fraction in binary IEEE 754 floating-point, repeated addition yields $0.9999999999999999$ followed by $1.0999999999999999$. The variable \texttt{x} never strictly equals \texttt{1.0}. Guard condition should always use inequalities (\texttt{while x < 1.0:}) or tolerance intervals.
\end{trapbox}

\begin{trapbox}{The Misconception of Loop \texttt{else}}
A common misconception is that the loop \texttt{else} executes whenever the loop condition is false. In reality, the loop condition is ALWAYS false when a loop exits normally. The \texttt{else} block is specifically a \textbf{"no-break"} clause:
\begin{lstlisting}[language=Python]
for x in [1, 2, 3]:
    if x == 2:
        break
else:
    print("Completed")  # Will NEVER execute because break occurred!
\end{lstlisting}
\end{trapbox}

\begin{trapbox}{Off-by-One Non-Inclusivity in \texttt{range()}}
The mathematical interval of \texttt{range(a, b)} is half-open: $[a, b) = \{x \in \mathbb{Z} \mid a \le x < b\}$.
Programmers frequently forget that \texttt{range(1, 10)} terminates at $9$, omitting $10$. To iterate over $N$ items inclusive of both endpoints, the upper bound must be explicitly written as $N + 1$.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following industrial script implements a 1D Gradient Descent optimization solver for finding the local minimum of a convex loss function, utilizing convergence thresholding, adaptive step sizes, and the \texttt{for-else} non-convergence detector.

\begin{lstlisting}[language=Python]
import math

def loss_function(w: float) -> float:
    """Quadratic loss: L(w) = (w - 3)^2 + 4"""
    return (w - 3.0) ** 2 + 4.0

def loss_derivative(w: float) -> float:
    """dL/dw = 2*(w - 3)"""
    return 2.0 * (w - 3.0)

def gradient_descent_1d(
    w_init: float,
    learning_rate: float = 0.1,
    tolerance: float = 1e-6,
    max_iters: int = 100
) -> dict:
    """
    Performs iterative gradient descent with early stopping and loop else validation.
    """
    w = w_init
    trajectory = []

    for step in range(1, max_iters + 1):
        grad = loss_derivative(w)
        loss = loss_function(w)
        trajectory.append((step, w, loss))

        # Check convergence using step size reduction
        delta_w = learning_rate * grad
        if abs(delta_w) < tolerance:
            return {
                "converged": True,
                "optimal_w": round(w, 6),
                "min_loss": round(loss, 6),
                "iterations": step,
                "trajectory_sample": trajectory[:3] + trajectory[-2:]
            }

        # Update weight parameter
        w -= delta_w
    else:
        # Loop else executes ONLY if max_iters was reached without convergence
        return {
            "converged": False,
            "optimal_w": round(w, 6),
            "min_loss": round(loss_function(w), 6),
            "iterations": max_iters,
            "warning": "Maximum iterations reached before meeting tolerance."
        }

# Execute optimization
result = gradient_descent_1d(w_init=10.0, learning_rate=0.2, tolerance=1e-5)
print("Optimization Status:", result["converged"])
print(f"Optimal Parameter: w* = {result['optimal_w']}, Iterations = {result['iterations']}")
# Output: Optimization Status: True
#         Optimal Parameter: w* = 3.0, Iterations = 31
\end{lstlisting}
