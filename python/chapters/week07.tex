\chapter{Functional Programming, Comprehensions \& Streaming Generators}

Modern high-performance data processing demands declarative elegance and memory efficiency. As datasets grow to millions of observations, allocating entire intermediate arrays in memory becomes a critical system bottleneck. Python bridges imperative control with \index{Functional Programming}\textbf{Functional Programming} abstractions, offering set-builder comprehensions, anonymous lambda transformations, and lazy \index{Generators}\textbf{Generators} driven by the iterator protocol and the \texttt{yield} keyword. Mastering these primitives allows machine learning practitioners to construct expressive, streaming data pipelines that process infinite or out-of-core data sequences in strictly $\mathcal{O}(1)$ working memory.

\section{Mathematical \& Computational Foundations}

\subsection{Set-Builder Isomorphism and Comprehension Calculus}

\begin{definitionbox}{Set-Builder Notation Isomorphism}
\index{Comprehensions} \index{Set-Builder Notation}
In mathematics, a set is defined declaratively using set-builder notation:
\begin{equation}
S = \{ f(x) \mid x \in X \land P(x) \}
\end{equation}
Python comprehensions provide a direct computational mapping:
\begin{enumerate}
    \item \textbf{List Comprehension:} \texttt{[f(x) for x in X if P(x)]} $\implies$ constructs ordered dynamic array.
    \item \textbf{Set Comprehension:} \texttt{\{f(x) for x in X if P(x)\}} $\implies$ constructs deduplicated hash set.
    \item \textbf{Dict Comprehension:} \texttt{\{k(x): v(x) for x in X if P(x)\}} $\implies$ constructs key-value hash map.
\end{enumerate}
In Python 3 (PEP 274/3115), all comprehensions execute within their own isolated function-level scope, preventing loop variables from polluting the enclosing namespace.
\end{definitionbox}

\subsection{The Python Iterator Protocol}

\begin{theorembox}{The Formal Iterator Protocol Invariant}
\index{Iterator Protocol} \index{StopIteration}
Python's iteration mechanism is governed by two complementary dunder methods:
\begin{enumerate}
    \item \textbf{Iterable Object:} Any container providing an \texttt{\_\_iter\_\_()} method that returns an iterator instance.
    \item \textbf{Iterator Object:} An object maintaining state that provides:
    \begin{itemize}
        \item \texttt{\_\_iter\_\_()}: Returns \texttt{self}.
        \item \texttt{\_\_next\_\_()}: Returns the next element in the sequence. When no elements remain, it must raise the \texttt{StopIteration} exception.
    \end{itemize}
\end{enumerate}
A \texttt{for} loop is syntactic sugar for this protocol:
\begin{lstlisting}[language=Python]
iterator = iter(collection)  # Calls collection.__iter__()
while True:
    try:
        item = next(iterator)  # Calls iterator.__next__()
        # execute loop body
    except StopIteration:
        break  # Clean termination
\end{lstlisting}
\end{theorembox}

\subsection{Generators and the \texttt{yield} Execution Mechanics}

\begin{theorembox}{Suspension and Resumption of Generator Frames}
\index{yield Keyword} \index{Generator Function}
A function containing the \texttt{yield} keyword is compiled as a \textbf{generator function}. Calling it does not execute the function body; instead, it returns a \textbf{generator-iterator} object.
\begin{itemize}
    \item When \texttt{next(gen)} is invoked, execution commences or resumes from its current instruction pointer until reaching a \texttt{yield expr} statement.
    \item The value of \texttt{expr} is returned to the caller, and the function's stack frame (including all local variables and instruction state) is \textbf{frozen in heap memory}.
    \item Subsequent \texttt{next(gen)} calls resume execution immediately after the \texttt{yield} statement.
    \item When the function exits (via \texttt{return} or end of body), Python automatically raises \texttt{StopIteration}.
\end{itemize}
\end{theorembox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Functional Composition and Equivalence}
In theoretical computer science, a filtering step followed by a mapping step can be written in terms of functional composition:
\begin{equation}
(f \circ \text{filter}_p)(X) \equiv [f(x) \text{ for } x \text{ in } X \text{ if } p(x)] \equiv \text{map}(f, \text{filter}(p, X))
\end{equation}
In modern Python, list comprehensions are preferred over raw \texttt{map} and \texttt{filter} with lambdas because comprehensions avoid the overhead of repeated lambda function call frames, executing directly at C-speed in the bytecode evaluation loop.

\subsection{Generator Expressions vs. List Comprehensions}
Replacing square brackets with parentheses transforms an eager comprehension into a lazy generator expression:
\begin{lstlisting}[language=Python]
import sys
# Eager: builds 10 million integers in memory
eager_list = [x**2 for x in range(10_000_000)]
print(sys.getsizeof(eager_list))  # ~85 Megabytes!

# Lazy: generates elements on demand
lazy_gen = (x**2 for x in range(10_000_000))
print(sys.getsizeof(lazy_gen))   # Only 112 bytes!
\end{lstlisting}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{Generators Are Single-Use (Exhaustion Trap)}
Unlike lists, iterators and generators have state and can only be traversed \textbf{exactly once}:
\begin{lstlisting}[language=Python]
gen = (x for x in [1, 2, 3])
print(list(gen))  # Output: [1, 2, 3]
print(list(gen))  # Output: [] -- Exhausted! No warning or error is raised.
\end{lstlisting}
If data needs to be passed to multiple consumers or processed in multiple epochs, either restart the generator function or store items in a persistent collection.
\end{trapbox}

\begin{trapbox}{Reading Nested Comprehensions Outside-In}
The order of \texttt{for} clauses in a nested comprehension matches the order of nested \texttt{for} statements in conventional loop blocks:
\begin{lstlisting}[language=Python]
matrix = [[1, 2], [3, 4]]
# Flattens matrix:
flat = [x for row in matrix for x in row]  # CORRECT!
\end{lstlisting}
Writing \texttt{[x for x in row for row in matrix]} is a syntax error because \texttt{row} is referenced before it is bound by the outer clause.
\end{trapbox}

\begin{trapbox}{The \texttt{map()} and \texttt{filter()} Iterator Trap in Python 3}
In Python 2, \texttt{map()} and \texttt{filter()} returned lists. In Python 3, they return lazy iterator objects:
\begin{lstlisting}[language=Python]
res = map(lambda x: x * 2, [1, 2, 3])
print(len(res))  # Raises TypeError: object of type 'map' has no len()!
\end{lstlisting}
To obtain length or access by index, the result must be explicitly materialized: \texttt{len(list(res))}.
\end{trapbox}

\begin{trapbox}{Comprehensions with Side Effects}
Never use comprehensions solely for side effects (such as printing or appending to external lists):
\begin{lstlisting}[language=Python]
# ANTI-PATTERN:
[print(x) for x in data]  # Allocates a list of None values purely to print!
\end{lstlisting}
Use a standard \texttt{for} loop when executing operations that do not yield a meaningful target collection.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following industrial script implements a Streaming Machine Learning Data Loader that generates synthetic regression batches, filters outliers on the fly, applies Min-Max normalization lazily, and yields mini-batches for Stochastic Gradient Descent.

\begin{lstlisting}[language=Python]
import random
from typing import Generator, List, Tuple

def streaming_data_source(n_samples: int) -> Generator[Tuple[float, float], None, None]:
    """Simulates an out-of-core continuous data stream: yields (x, y)."""
    for _ in range(n_samples):
        x = random.uniform(-10.0, 10.0)
        # Underlying model: y = 2.5*x - 1.2 + Gaussian noise
        noise = random.gauss(0.0, 0.5)
        y = 2.5 * x - 1.2 + noise
        yield (round(x, 4), round(y, 4))

def filter_outliers(
    stream: Generator[Tuple[float, float], None, None],
    x_bound: float = 8.0
) -> Generator[Tuple[float, float], None, None]:
    """Lazy filter removing samples beyond boundary limits."""
    for x, y in stream:
        if abs(x) <= x_bound:
            yield (x, y)

def batch_generator(
    stream: Generator[Tuple[float, float], None, None],
    batch_size: int = 4
) -> Generator[List[Tuple[float, float]], None, None]:
    """Chunks an infinite or long stream into discrete mini-batches for SGD."""
    batch = []
    for sample in stream:
        batch.append(sample)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch  # Remaining residual batch

# Assemble end-to-end streaming ML generator pipeline
random.seed(42)
raw_stream = streaming_data_source(n_samples=20)
clean_stream = filter_outliers(raw_stream, x_bound=7.0)
mini_batches = batch_generator(clean_stream, batch_size=4)

print("Streaming Mini-Batch Pipeline Active:")
for batch_idx, batch in enumerate(mini_batches, 1):
    x_mean = round(sum(item[0] for item in batch) / len(batch), 3)
    y_mean = round(sum(item[1] for item in batch) / len(batch), 3)
    print(f"Batch {batch_idx}: Size = {len(batch)}, Centroid = ({x_mean}, {y_mean})")
# Pipeline executes in constant O(1) memory!
\end{lstlisting}
