\chapter{Tuples, Dictionaries, Sets \& Hash Table Mechanics}

Scalable data engineering and modern algorithmic pipelines require specialized data structures engineered for fast associative lookup, strict immutability, and discrete mathematical set operations. While dynamic lists provide sequential indexing, Python's \index{Dictionaries}\textbf{Dictionaries} and \index{Sets}\textbf{Sets} leverage hash tables to achieve amortized $\mathcal{O}(1)$ search, insertion, and deletion. Concurrently, \index{Tuples}\textbf{Tuples} provide memory-efficient immutable records that serve as dependable dictionary keys and structural schemas. Understanding the mathematical prerequisites of hashability, CPython's compact hash table architecture, and set-theoretic algebra is indispensable for constructing high-throughput machine learning feature pipelines.

\section{Mathematical \& Computational Foundations}

\subsection{Hash Functions and the Hashability Protocol}

\begin{definitionbox}{The Formal Hashability Invariant}
\index{Hash Function} \index{Hashability}
A hash function is a deterministic mathematical mapping $h: \mathcal{K} \to \mathbb{Z}$ that projects an arbitrary key from domain $\mathcal{K}$ onto an integer hash code.
In Python, an object $x$ is \textbf{hashable} if and only if:
\begin{enumerate}
    \item It possesses a hash code produced by \texttt{\_\_hash\_\_()} that remains strictly invariant across its entire lifecycle.
    \item It implements an equality method \texttt{\_\_eq\_\_()} satisfying the consistency invariant:
    \begin{equation}
    x == y \implies \text{hash}(x) == \text{hash}(y)
    \end{equation}
    \item It can be compared for equivalence with other objects reflexively, symmetrically, and transitively.
\end{enumerate}
All immutable built-in primitive types (\texttt{int}, \texttt{float}, \texttt{str}, \texttt{bytes}, \texttt{frozenset}) are hashable. Mutable containers (\texttt{list}, \texttt{dict}, \texttt{set}) are explicitly \textbf{unhashable} because in-place mutation would alter their contents and disrupt hash table bucket locations, raising a \texttt{TypeError: unhashable type}.
\end{definitionbox}

\subsection{CPython Compact Hash Table Architecture}

\begin{theorembox}{Compact and Ordered Hash Table Storage}
\index{Compact Dict} \index{Collision Resolution}
Since Python 3.6, dictionaries use a compact memory layout that preserves insertion order while reducing memory footprint by approximately 25\%.
The architecture decouples bucket index hashing from entry storage:
\begin{enumerate}
    \item \textbf{Sparse Indices Array:} A power-of-two table of size $M$ storing integer offsets pointing to entries:
    \begin{equation}
    \text{bucket} = h(k) \pmod M
    \end{equation}
    \item \textbf{Dense Entries Array:} A sequentially appended array storing 24-byte structs:
    \begin{lstlisting}[language=C]
    typedef struct {
        Py_hash_t me_hash;
        PyObject *me_key;
        PyObject *me_value;
    } PyDictKeyEntry;
    \end{lstlisting}
    \item \textbf{Collision Resolution via Open Addressing:} If bucket $i$ is occupied by an unequal key, CPython resolves collisions using a pseudo-random perturbation sequence:
    \begin{equation}
    i_{k+1} = (5 \cdot i_k + 1 + \text{perturb}) \pmod M, \quad \text{where } \text{perturb} \leftarrow \text{perturb} \gg 5
    \end{equation}
    This ensures complete traversal of all $M$ slots without clustering.
\end{enumerate}
\end{theorembox}

\subsection{Discrete Set Theory and Jaccard Similarity}

\begin{definitionbox}{Set Algebra and Similarity Metric}
\index{Set Operations} \index{Jaccard Similarity}
Given two sets $A, B \subseteq \mathcal{U}$:
\begin{enumerate}
    \item \textbf{Intersection ($A \cap B$ / \texttt{A \& B}):} $\{x \mid x \in A \land x \in B\}$.
    \item \textbf{Union ($A \cup B$ / \texttt{A | B}):} $\{x \mid x \in A \lor x \in B\}$.
    \item \textbf{Relative Complement / Difference ($A \setminus B$ / \texttt{A - B}):} $\{x \mid x \in A \land x \notin B\}$.
    \item \textbf{Symmetric Difference ($A \triangle B$ / \texttt{A \^{} B}):} $(A \setminus B) \cup (B \setminus A)$.
    \item \textbf{Jaccard Similarity Coefficient $J(A, B)$:} A normalized metric measuring overlap:
    \begin{equation}
    J(A, B) = \frac{|A \cap B|}{|A \cup B|} = \frac{|A \cap B|}{|A| + |B| - |A \cap B|} \in [0, 1]
    \end{equation}
\end{enumerate}
\end{definitionbox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Average-Case $\mathcal{O}(1)$ vs Worst-Case $\mathcal{O}(n)$ Complexity}
Under the Uniform Hashing Assumption, the load factor $\alpha = \frac{n}{M}$ is maintained below $\frac{2}{3}$ via dynamic table resizing. When $\alpha \le \frac{2}{3}$, the expected number of probes required to locate or insert a key is bounded by:
\begin{equation}
\mathbb{E}[\text{Probes}] \le \frac{1}{1 - \alpha} \le \frac{1}{1 - 2/3} = 3
\end{equation}
Thus, dictionary and set operations operate in $\mathcal{O}(1)$ average time. However, if an adversary crafts keys that produce identical hash residues (hash collision attack), all lookups degrade to linear search $\mathcal{O}(n)$. To mitigate this, Python randomizes string hash seeds on process startup (PEP 456).

\subsection{Extended Tuple Unpacking}
Python allows sequence unpacking with arbitrary variable-length slicing using the starred expression \texttt{*rest}:
\begin{lstlisting}[language=Python]
record = ("US", "CA", 2024, 105.4, 98.2, "ACTIVE")
country, state, year, *readings, status = record
# country = "US", state = "CA", year = 2024
# readings = [105.4, 98.2] (gathered into a list)
# status = "ACTIVE"
\end{lstlisting}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{Tuples Containing Mutable Objects Are Unhashable}
Immutability of a tuple is shallow: it prevents changing the pointer references it holds, but does NOT make the referenced objects immutable!
\begin{lstlisting}[language=Python]
t = ([1, 2], 3)
# Attempting to use t as a dictionary key or in a set:
d = {t: "valid"}  # CRITICAL BUG!
# Raises TypeError: unhashable type: 'list'
\end{lstlisting}
A tuple is only hashable if \textbf{every element inside it} is recursively hashable.
\end{trapbox}

\begin{trapbox}{Modifying a Dictionary During Iteration}
Never alter the keys of a dictionary while directly iterating across it:
\begin{lstlisting}[language=Python]
data = {"a": 1, "b": 2, "c": 3}
for k in data:
    if data[k] % 2 == 0:
        del data[k]  # Raises RuntimeError: dictionary changed size during iteration!
\end{lstlisting}
To delete safely, iterate over a snapshot of the keys: \texttt{for k in list(data.keys()):}.
\end{trapbox}

\begin{trapbox}{The Single-Element Tuple Syntax Pitfall}
Parentheses alone do not construct a tuple; the \textbf{comma} constructs a tuple:
\begin{lstlisting}[language=Python]
x = (42)    # Type is int, NOT tuple! (Parentheses treated as grouping)
y = (42,)   # Type is tuple!
\end{lstlisting}
Passing \texttt{(42)} to a function expecting a tuple parameter triggers type errors or unwanted sequence unpacking bugs.
\end{trapbox}

\begin{trapbox}{Boolean and Integer Key Collisions in Dictionaries}
In Python, \texttt{bool} is a direct subclass of \texttt{int}, where $\text{hash}(\text{True}) == \text{hash}(1) == 1$ and $\text{True} == 1$.
\begin{lstlisting}[language=Python]
d = {True: "Alpha", 1: "Beta"}
print(d)       # Output: {True: 'Beta'}
print(len(d))  # Output: 1!
\end{lstlisting}
Because \texttt{1} matches \texttt{True} in both hash code and equality, Python treats them as the identical key, overwriting the value while preserving the original key object!
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following production script implements an NLP Text Processing \& Vocabulary Pipeline: tokenization, vocabulary indexing, unigram frequency counting, stop-word set difference filtering, and pairwise Jaccard text similarity.

\begin{lstlisting}[language=Python]
from typing import List, Dict, Set, Tuple

class TextCorpusProcessor:
    def __init__(self, stopwords: Set[str]):
        self.stopwords = frozenset(stopwords)  # Immutable hashable set
        self.vocab2idx: Dict[str, int] = {}
        self.idx2vocab: Dict[int, str] = {}

    def tokenize(self, text: str) -> List[str]:
        """Cleans and extracts lower-cased alpha tokens."""
        clean_words = []
        for word in text.lower().split():
            sanitized = "".join(ch for ch in word if ch.isalnum())
            if sanitized and sanitized not in self.stopwords:
                clean_words.append(sanitized)
        return clean_words

    def fit_vocabulary(self, documents: List[str]) -> None:
        """Constructs forward and inverse vocabulary mappings."""
        unique_tokens = set()
        for doc in documents:
            unique_tokens.update(self.tokenize(doc))

        # Sort for deterministic vocabulary indexing
        for idx, token in enumerate(sorted(unique_tokens)):
            self.vocab2idx[token] = idx
            self.idx2vocab[idx] = token

    def document_frequencies(self, text: str) -> Dict[str, int]:
        """Computes unigram term frequencies."""
        tokens = self.tokenize(text)
        freq_map: Dict[str, int] = {}
        for token in tokens:
            freq_map[token] = freq_map.get(token, 0) + 1
        return freq_map

    @staticmethod
    def jaccard_similarity(doc1_tokens: Set[str], doc2_tokens: Set[str]) -> float:
        """Computes Jaccard similarity: |A & B| / |A | B|."""
        if not doc1_tokens and not doc2_tokens:
            return 1.0
        intersection = len(doc1_tokens & doc2_tokens)
        union = len(doc1_tokens | doc2_tokens)
        return round(intersection / union, 4)

# Demonstration
corpus = [
    "Machine learning models require clean training data",
    "Deep neural network models learn representations from data"
]
stop_words = {"from", "in", "the", "and", "to"}

processor = TextCorpusProcessor(stopwords=stop_words)
processor.fit_vocabulary(corpus)

tokens1 = set(processor.tokenize(corpus[0]))
tokens2 = set(processor.tokenize(corpus[1]))
similarity = processor.jaccard_similarity(tokens1, tokens2)

print("Vocabulary Size:", len(processor.vocab2idx))
print("Vocabulary Index:", processor.vocab2idx)
print("Document 1 Tokens:", tokens1)
print("Document 2 Tokens:", tokens2)
print("Jaccard Similarity:", similarity)
# Output:
# Jaccard Similarity: 0.2222 (Shared: {'models', 'data'})
\end{lstlisting}
