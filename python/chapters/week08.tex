\chapter{File I/O, Context Managers \& Exception Architecture}

Production data science pipelines rarely operate in isolation with clean, in-memory datasets. Data originates from heterogeneous external sources---network sockets, streaming sensors, unstructured text logs, and multi-gigabyte disk files. In these stochastic environments, operations are prone to external disruptions: missing files, network dropouts, corrupted binary records, and numerical overflows. Python governs input/output and runtime error handling through \index{Context Managers}\textbf{Context Managers} and a structured \index{Exception Handling}\textbf{Exception Hierarchy}. Understanding the low-level operating system file descriptor lifecycle, the \texttt{\_\_enter\_\_}/\texttt{\_\_exit\_\_} protocol, and the exact evaluation order of the \texttt{try-except-else-finally} engine is essential for building mission-critical machine learning systems that fail safely without corrupting disk state or leaking system resources.

\section{Mathematical \& Computational Foundations}

\subsection{Operating System I/O and File Descriptors}

\begin{definitionbox}{File Descriptors, Buffering, and Encoding}
\index{File Descriptors} \index{I/O Buffering}
When Python opens a file on disk:
\begin{enumerate}
    \item The operating system allocates an integer \textbf{file descriptor} ($fd$) in the process's file table.
    \item \textbf{User-Space Buffering:} To avoid expensive kernel syscalls on every character, standard Python file streams maintain an internal memory buffer (typically $4$ to $8$ KB). Data written via \texttt{f.write()} resides in RAM until the buffer fills, the stream is flushed via \texttt{f.flush()}, or the file descriptor is released via \texttt{f.close()}.
    \item \textbf{Encoding Layer:} In text mode (\texttt{'r'}, \texttt{'w'}), Python decodes binary bytes into Unicode strings using an encoding codec (defaulting to UTF-8). In binary mode (\texttt{'rb'}, \texttt{'wb'}), raw \texttt{bytes} objects are read and written directly without newline translation or character decoding.
\end{enumerate}
Operating systems enforce a hard limit on open file descriptors per process (e.g., 1024 on Linux/macOS). Failing to close files leads to descriptor leaks, crashing long-running training loops.
\end{definitionbox}

\subsection{The Context Management Protocol (PEP 343)}

\begin{theorembox}{The \texttt{\_\_enter\_\_} and \texttt{\_\_exit\_\_} Invariants}
\index{Context Management Protocol} \index{with Statement}
The \texttt{with} statement provides deterministic resource acquisition and release regardless of whether code blocks complete normally or terminate with an unhandled exception:
\begin{lstlisting}[language=Python]
with expression as target:
    suite
\end{lstlisting}
The exact operational semantics:
\begin{enumerate}
    \item Evaluates \texttt{expression} to obtain a context manager object $M$.
    \item Invokes $M\text{.\_\_enter\_\_()}$. Its return value is bound to \texttt{target}.
    \item Executes the code in \texttt{suite}.
    \item \textbf{Normal Termination:} When \texttt{suite} completes without error, Python invokes:
    \begin{equation}
    M.\_\_\text{exit}\_\_(\text{None}, \text{None}, \text{None})
    \end{equation}
    \item \textbf{Exceptional Termination:} If an exception $E$ occurs within \texttt{suite}, Python invokes:
    \begin{equation}
    \text{suppress} = M.\_\_\text{exit}\_\_(\text{type}(E), E, \text{traceback})
    \end{equation}
    If $M\text{.\_\_exit\_\_()}$ returns \texttt{True}, the exception is \textbf{suppressed}; otherwise, $E$ is re-raised automatically.
\end{enumerate}
\end{theorembox}

\subsection{The Exception Hierarchy and Catching Semantics}

\begin{theorembox}{The Class Inheritance Exception Model}
\index{Exception Hierarchy}
All built-in exceptions form an object-oriented class hierarchy rooted at \texttt{BaseException}:
\begin{center}
\small
\texttt{BaseException} $\longrightarrow$ \texttt{KeyboardInterrupt}, \texttt{SystemExit}, \texttt{GeneratorExit}\\
$\rotatebox[origin=c]{270}{$\longrightarrow$}$ \textbf{\texttt{Exception}} $\longrightarrow$ \texttt{ArithmeticError}, \texttt{LookupError}, \texttt{OSError}, \texttt{ValueError}, \texttt{TypeError}
\end{center}
An \texttt{except TargetError:} clause catches any exception whose class is identical to \texttt{TargetError} or is a \textbf{subclass} of \texttt{TargetError}.
\textbf{Compiler Invariant:} Never catch \texttt{BaseException} in normal application code; doing so intercepts \texttt{KeyboardInterrupt} (Ctrl+C) and \texttt{SystemExit}, rendering the program unresponsive to manual termination signals.
\end{theorembox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{EAFP versus LBYL Paradigms in Python}
In programming languages like C, developers follow \textbf{LBYL} ("Look Before You Leap"):
\begin{lstlisting}[language=Python]
# LBYL Paradigm (Prone to Race Conditions):
if os.path.exists(file_path):
    f = open(file_path, "r")
\end{lstlisting}
Between checking \texttt{os.path.exists()} and invoking \texttt{open()}, an external process could delete or lock the file (a Time-of-Check to Time-of-Use [TOCTOU] race condition).
Python strongly advocates \textbf{EAFP} ("Easier to Ask for Forgiveness than Permission"):
\begin{lstlisting}[language=Python]
# EAFP Paradigm (Atomic and Thread-Safe):
try:
    with open(file_path, "r") as f:
        data = f.read()
except FileNotFoundError:
    handle_missing_file()
\end{lstlisting}
EAFP is faster in common paths where exceptions are infrequent, avoiding duplicate filesystem inquiries.

\subsection{Custom Domain Exception Hierarchies}
In machine learning engineering, standard exceptions like \texttt{ValueError} lack domain specificity. We define modular custom hierarchies:
\begin{lstlisting}[language=Python]
class MLEngineError(Exception):
    """Base exception for machine learning pipeline failures."""
    pass

class DataSchemaError(MLEngineError):
    """Raised when incoming features violate model schema."""
    pass

class ModelNotTrainedError(MLEngineError):
    """Raised when prediction is invoked prior to fitting."""
    pass
\end{lstlisting}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{The Bare \texttt{except:} Anti-Pattern}
Writing a bare \texttt{except:} without specifying an exception class catches \texttt{BaseException}:
\begin{lstlisting}[language=Python]
try:
    run_training_loop()
except:  # CATASTROPHIC BUG!
    print("An error occurred.")
\end{lstlisting}
This prevents users from stopping the process using Ctrl+C (\texttt{KeyboardInterrupt}) or programmatic termination (\texttt{sys.exit()}). Always write at minimum: \texttt{except Exception:}.
\end{trapbox}

\begin{trapbox}{The \texttt{finally} Return Value Override Trap}
Executing a \texttt{return} statement inside a \texttt{finally} block silently discards any active exception:
\begin{lstlisting}[language=Python]
def risky_calculation():
    try:
        return 10 / 0  # ZeroDivisionError
    finally:
        return 42      # SILENTLY SWALLOWS THE ZERO DIVISION!

print(risky_calculation())  # Prints 42! ZeroDivisionError is lost.
\end{lstlisting}
Never place \texttt{return}, \texttt{break}, or \texttt{continue} statements inside a \texttt{finally} block.
\end{trapbox}

\begin{trapbox}{Text Mode Line Ending Translations Across Operating Systems}
When opening files in text mode on Windows, Python automatically translates UNIX line endings (\texttt{\textbackslash n}) to Windows CRLF (\texttt{\textbackslash r\textbackslash n}) on write, and reverse on read. For binary datasets (such as NumPy `.npy` arrays, images, or pickled models), opening in text mode corrupts binary bytes. Always open non-text data with \texttt{'rb'} or \texttt{'wb'}.
\end{trapbox}

\begin{trapbox}{Resource Leaks from Manual \texttt{.close()} Calls}
Relying on manual \texttt{f.close()} statements without a \texttt{try-finally} or \texttt{with} context manager guarantees resource leaks if an exception occurs between opening and closing the file handle.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following industrial script implements an Atomic File Writer Context Manager (writing to a temporary file and atomically swapping on success to prevent corruptions during crashes) and a Robust CSV Feature Ingestion Engine with schema validation.

\begin{lstlisting}[language=Python]
import os
import tempfile
from typing import List, Dict, Generator

class AtomicFileWriter:
    """
    Context manager guaranteeing atomic file writes.
    Writes to a temporary file and atomically replaces target file upon clean exit.
    """
    def __init__(self, target_filepath: str):
        self.target_path = target_filepath
        self.temp_file = None

    def __enter__(self):
        dir_name = os.path.dirname(self.target_path) or "."
        self.temp_file = tempfile.NamedTemporaryFile(
            mode="w", dir=dir_name, delete=False, encoding="utf-8"
        )
        return self.temp_file

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.temp_file.close()
        if exc_type is None:
            # Atomic replacement on clean execution
            os.replace(self.temp_file.name, self.target_path)
            return False  # Propagate nothing
        else:
            # Clean up temporary file on failure without touching target file
            if os.path.exists(self.temp_file.name):
                os.remove(self.temp_file.name)
            return False  # Propagate exception to caller

def parse_dataset_stream(filepath: str) -> Generator[Dict[str, float], None, None]:
    """
    Robust generator streaming and parsing numeric CSV records with error logging.
    """
    if not os.path.exists(filepath):
        raise FileNotFoundError(f"Source file not located: {filepath}")

    with open(filepath, "r", encoding="utf-8") as f:
        header = f.readline().strip().split(",")
        for line_num, line in enumerate(f, start=2):
            raw_line = line.strip()
            if not raw_line or raw_line.startswith("#"):
                continue  # Skip empty lines and comments
            parts = raw_line.split(",")
            try:
                record = {col: float(val) for col, val in zip(header, parts)}
                yield record
            except (ValueError, TypeError) as err:
                # EAFP logging of corrupted records
                print(f"[WARNING] Line {line_num} corrupted: {raw_line} -> {err}")
                continue

# Demonstration: Write atomic dataset
csv_filename = "training_data.csv"
sample_data = "feat1,feat2,target\n1.2,3.4,10.5\n# corrupted row below\n2.1,bad_data,15.2\n3.0,4.5,22.1\n"

with AtomicFileWriter(csv_filename) as f:
    f.write(sample_data)

# Stream and parse clean records
print("Streaming Parsed Records:")
for row in parse_dataset_stream(csv_filename):
    print("Clean Record:", row)

# Clean up demonstration file
if os.path.exists(csv_filename):
    os.remove(csv_filename)
# Output:
# [WARNING] Line 4 corrupted: 2.1,bad_data,15.2 -> could not convert string to float: 'bad_data'
# Clean Record: {'feat1': 1.2, 'feat2': 3.4, 'target': 10.5}
# Clean Record: {'feat1': 3.0, 'feat2': 4.5, 'target': 22.1}
\end{lstlisting}
