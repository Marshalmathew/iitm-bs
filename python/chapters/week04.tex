\chapter{Lists, Dynamic Arrays \& Matrix Algorithms}

Linear data structures and multi-dimensional matrices form the structural bedrock of modern data pipelines and machine learning frameworks. In Python, the built-in \index{List}\textbf{List} is far more than a conventional fixed-size array: it is an engineered \textbf{dynamic array of object references}. Understanding the internal memory layout of CPython's list implementation, the subtleties of reference aliasing versus deep copying, and the linear algebraic mechanics of pure-Python vector and matrix algorithms is essential for writing performant, bug-free computational code before transitioning to hardware-accelerated libraries like NumPy.

\end{itemize}

\section{Mathematical \& Computational Foundations}

\subsection{CPython Dynamic Array Memory Architecture}

\begin{definitionbox}{Internal Representation of \texttt{PyListObject}}
\index{PyListObject} \index{Dynamic Array}
In standard CPython, a list is implemented not as a linked list or raw contiguous block of values, but as a \textbf{contiguous array of 64-bit pointers} to heap-allocated \texttt{PyObject} instances:
\begin{lstlisting}[language=C]
typedef struct {
    PyObject_VAR_HEAD
    PyObject **ob_item;  // Pointer to array of pointers
    Py_ssize_t allocated; // Allocated memory capacity
} PyListObject;
\end{lstlisting}
Because the array holds pointers rather than raw data:
\begin{enumerate}
    \item Elements can be \textbf{heterogeneous} (integers, strings, floats, other lists).
    \item \textbf{Random access by index} is strictly $\mathcal{O}(1)$ via pointer arithmetic:
    \begin{equation}
    \text{Address}(L[i]) = \text{BaseAddress} + i \times 8 \text{ bytes}
    \end{equation}
    \item To avoid reallocating memory on every \texttt{.append()}, Python uses an \textbf{over-allocation growth formula}:
    \begin{equation}
    \text{new\_allocated} = \text{new\_size} + (\text{new\_size} \gg 3) + (\text{new\_size} < 9 \mathrel{?} 3 : 6)
    \end{equation}
    This amortizes memory reallocations, making \texttt{append()} take \textbf{amortized $\mathcal{O}(1)$ time}, while insertions at arbitrary indices require shifting pointers, taking $\mathcal{O}(n)$ time.
\end{enumerate}
\end{definitionbox}

\subsection{Aliasing, Shallow Copying, and Deep Copying}

\begin{theorembox}{The Reference Assignment Invariant}
\index{Aliasing} \index{Shallow Copy} \index{Deep Copy}
Let $A$ be a mutable list. The assignment statement:
\begin{lstlisting}[language=Python]
B = A
\end{lstlisting}
creates a new name binding $B$ pointing to the \textbf{exact same memory address} as $A$ ($\text{id}(A) == \text{id}(B)$). Any mutation performed through $B$ immediately reflects in $A$.
To create an independent clone:
\begin{itemize}
    \item \textbf{Shallow Copy (\texttt{C = A.copy()} or \texttt{C = A[:]}):} Allocates a new \texttt{PyListObject} with its own array of pointers, but copies the pointer addresses. If elements are themselves mutable (e.g., inner lists of a matrix), inner mutations remain shared!
    \item \textbf{Deep Copy (\texttt{import copy; D = copy.deepcopy(A)}):} Recursively clones all nested container objects and their contents, ensuring complete memory isolation.
\end{itemize}
\end{theorembox}

\subsection{Linear Algebraic Matrix Operations in Pure Python}

\begin{definitionbox}{Vector and Matrix Algebra Formulations}
\index{Dot Product} \index{Matrix Multiplication}
A 2D matrix $A \in \mathbb{R}^{m \times k}$ is represented as a nested list of $m$ rows, each containing $k$ numeric scalars.
\begin{enumerate}
    \item \textbf{Vector Dot Product:} For $\mathbf{u}, \mathbf{v} \in \mathbb{R}^k$:
    \begin{equation}
    \langle \mathbf{u}, \mathbf{v} \rangle = \mathbf{u} \cdot \mathbf{v} = \sum_{p=1}^k u_p v_p
    \end{equation}
    \item \textbf{Matrix Transpose:} For $A \in \mathbb{R}^{m \times k}$, $A^T \in \mathbb{R}^{k \times m}$ satisfies:
    \begin{equation}
    (A^T)_{ji} = A_{ij}, \quad \forall 1 \le i \le m, \, 1 \le j \le k
    \end{equation}
    \item \textbf{Matrix Multiplication:} For $A \in \mathbb{R}^{m \times k}$ and $B \in \mathbb{R}^{k \times n}$, the product $C = AB \in \mathbb{R}^{m \times n}$ has elements:
    \begin{equation}
    C_{ij} = \sum_{p=1}^k A_{ip} B_{pj}
    \end{equation}
    Executing this in pure Python requires three nested loops, running in $\mathcal{O}(m \cdot k \cdot n)$ time.
\end{enumerate}
\end{definitionbox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Selection Sort Complexity Derivation}
Selection sort operates by finding the minimal element in the unsorted suffix and swapping it into the prefix:
\begin{equation}
T(n) = \sum_{i=0}^{n-2} (n - 1 - i) = (n - 1) + (n - 2) + \dots + 1 = \frac{n(n - 1)}{2}
\end{equation}
The number of comparison operations is strictly invariant to input ordering: both best-case, average-case, and worst-case comparison counts are $\Theta(n^2)$. However, selection sort performs at most $n - 1$ memory swaps ($\mathcal{O}(n)$ writes), making it historically useful when memory writes are exceptionally expensive.

\subsection{In-Place Mutation versus Returning New Sequences}
Python maintains a strict convention across sequence APIs:
\begin{itemize}
    \item \textbf{In-place mutating methods} (e.g., \texttt{.sort()}, \texttt{.reverse()}, \texttt{.append()}) return \texttt{None} to explicitly prevent chaining bugs and signal that the original object was altered.
    \item \textbf{Pure functions} (e.g., \texttt{sorted()}, \texttt{reversed()}, \texttt{list + list}) allocate and return an entirely new object, leaving the original unchanged.
\end{itemize}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{The Repeated Inner List Multiplication Trap}
Creating a 2D matrix using list multiplication is one of the most notorious Python bugs:
\begin{lstlisting}[language=Python]
# Attempting to initialize a 3x3 zero matrix:
matrix = [[0] * 3] * 3  # CRITICAL BUG!
matrix[0][0] = 99
print(matrix)  # Output: [[99, 0, 0], [99, 0, 0], [99, 0, 0]]
\end{lstlisting}
The outer multiplication \texttt{[row] * 3} does not clone the inner list; it creates three references pointing to the \textbf{single identical row} in heap memory! Modifying any row modifies all rows.
\textbf{Correct Construction:}
\begin{lstlisting}[language=Python]
matrix = [[0 for _ in range(3)] for _ in range(3)]  # 3 distinct rows
\end{lstlisting}
\end{trapbox}

\begin{trapbox}{The \texttt{.sort()} Return Value Trap}
Because in-place sorting mutates the list and returns \texttt{None}:
\begin{lstlisting}[language=Python]
scores = [45, 12, 89, 32]
sorted_scores = scores.sort()  # BUG!
print(sorted_scores)  # Prints: None! scores was sorted, but sorted_scores is None.
\end{lstlisting}
Use \texttt{scores.sort()} alone, or assign \texttt{sorted\_scores = sorted(scores)}.
\end{trapbox}

\begin{trapbox}{Shallow Copying Nested Lists}
Writing \texttt{B = A[:]} or \texttt{B = A.copy()} creates an independent outer list, but copies references to inner lists:
\begin{lstlisting}[language=Python]
A = [[1, 2], [3, 4]]
B = A.copy()
B[0][0] = 999
print(A)  # Output: [[999, 2], [3, 4]] -- A was unexpectedly mutated!
\end{lstlisting}
For nested structures, always use \texttt{copy.deepcopy(A)}.
\end{trapbox}

\begin{trapbox}{Appending a List to Itself (Infinite Self-Reference)}
Because lists hold pointers to objects:
\begin{lstlisting}[language=Python]
lst = [1, 2]
lst.append(lst)
print(lst)  # Output: [1, 2, [...]]
\end{lstlisting}
The list now contains a cyclic pointer back to its own header. Python's printer safely detects recursion and prints \texttt{[...]}, but naive recursive algorithms traversing this list will trigger a \texttt{RecursionError}.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following production script implements a pure-Python Matrix Engine that validates rectangular dimensions, computes transpositions, performs matrix multiplication, and calculates the Gram Matrix ($X^T X$) used in linear regression normal equations.

\begin{lstlisting}[language=Python]
from typing import List

def matrix_transpose(matrix: List[List[float]]) -> List[List[float]]:
    """Computes the transpose A^T of an m x n matrix."""
    if not matrix or not matrix[0]:
        return []
    m, n = len(matrix), len(matrix[0])
    return [[matrix[r][c] for r in range(m)] for c in range(n)]

def matrix_multiply(A: List[List[float]], B: List[List[float]]) -> List[List[float]]:
    """
    Computes matrix product C = A x B.
    Validates inner dimension compatibility (cols(A) == rows(B)).
    """
    rows_A, cols_A = len(A), len(A[0])
    rows_B, cols_B = len(B), len(B[0])

    if cols_A != rows_B:
        raise ValueError(f"Dimension mismatch: A has {cols_A} cols, B has {rows_B} rows.")

    # Initialize zero matrix of dimensions rows_A x cols_B
    C = [[0.0 for _ in range(cols_B)] for _ in range(rows_A)]

    # 3-loop matrix multiplication
    for i in range(rows_A):
        for j in range(cols_B):
            dot_sum = 0.0
            for k in range(cols_A):
                dot_sum += A[i][k] * B[k][j]
            C[i][j] = round(dot_sum, 6)

    return C

def compute_gram_matrix(X: List[List[float]]) -> List[List[float]]:
    """Computes the Gram Matrix G = X^T * X for feature matrix X."""
    X_T = matrix_transpose(X)
    return matrix_multiply(X_T, X)

# Demonstration with a 3x2 feature matrix
feature_matrix = [
    [1.0, 2.0],
    [1.0, 3.0],
    [1.0, 5.0]
]

gram = compute_gram_matrix(feature_matrix)
print("Gram Matrix (X^T * X):")
for row in gram:
    print(row)
# Output:
# [3.0, 10.0]
# [10.0, 38.0]
\end{lstlisting}
