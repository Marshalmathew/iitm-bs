\chapter{Functions, Scopes, Closures \& Modular Architecture}

Modular abstraction is the defining principle of scalable software engineering. In Python, functions are not merely subroutines; they are \index{First-Class Objects}\textbf{first-class objects} that can be dynamically constructed, bound to identifiers, passed as arguments to higher-order algorithms, and returned from other functions. Furthermore, Python evaluates function parameters through \textbf{call-by-object-reference} (sharing) and resolves identifiers via the strict lexical hierarchy of the \textbf{LEGB rule}. Understanding parameter binding mechanics, mutable default argument traps, closures, and variable-length argument unpacking is essential for designing robust, production-grade machine learning pipelines and custom estimator frameworks.

\end{itemize}

\section{Mathematical \& Computational Foundations}

\subsection{Parameter Passing: Call-by-Object-Reference}

\begin{definitionbox}{Evaluation Strategy: Call-by-Sharing}
\index{Call-by-Sharing} \index{Parameter Passing}
Python does not use traditional "call-by-value" (cloning values) nor "call-by-reference" (passing pointers to variable boxes). It implements \textbf{call-by-object-reference} (call-by-sharing):
\begin{enumerate}
    \item When a function is called, the parameter names in the local scope are bound directly to the \textbf{exact heap objects} passed by the caller.
    \item \textbf{Immutable Arguments (\texttt{int}, \texttt{float}, \texttt{str}, \texttt{tuple}):} Reassigning the parameter inside the function binds the local name to a new object; the caller's variable remains unchanged.
    \item \textbf{Mutable Arguments (\texttt{list}, \texttt{dict}, \texttt{set}):} In-place mutations performed on the parameter (e.g., \texttt{.append()}, slice modification) mutate the underlying heap object, immediately impacting the caller's state.
\end{enumerate}
\end{definitionbox}

\subsection{The LEGB Namespace Resolution Hierarchy}

\begin{theorembox}{The LEGB Rule and Lexical Scoping}
\index{LEGB Rule} \index{Variable Scope}
When an identifier $x$ is referenced inside a function, Python searches four concentric namespaces in strict lexical order:
\begin{equation}
\text{Local (L)} \longrightarrow \text{Enclosing (E)} \longrightarrow \text{Global (G)} \longrightarrow \text{Built-in (B)}
\end{equation}
\begin{enumerate}
    \item \textbf{Local (L):} Names assigned within the current executing function body.
    \item \textbf{Enclosing (E):} Names in the local scope of any statically enclosing outer functions (from inner to outer).
    \item \textbf{Global (G):} Names assigned at the top-level of the current module file.
    \item \textbf{Built-in (B):} Pre-assigned names provided by the Python runtime (\texttt{len}, \texttt{range}, \texttt{ValueError}).
\end{enumerate}
\textbf{Compiler Invariant:} If a variable is assigned anywhere within a function body without an explicit \texttt{global} or \texttt{nonlocal} declaration, Python flags it as \textbf{purely Local} across the entire function at compile time.
\end{theorembox}

\subsection{Function Signature Grammar: Positional and Keyword Controls}

Python (PEP 570) provides granular control over how parameters are bound:
\begin{lstlisting}[language=Python]
def model_fit(data, target, /, weight=None, *, metric="mse", **kwargs):
    pass
\end{lstlisting}
\begin{itemize}
    \item \textbf{Positional-Only (\texttt{/}):} Parameters preceding \texttt{/} must be passed as positional arguments; passing them by keyword raises \texttt{TypeError}.
    \item \textbf{Positional or Keyword:} Parameters between \texttt{/} and \texttt{*} can be passed positionally or by keyword.
    \item \textbf{Keyword-Only (\texttt{*}):} Parameters following \texttt{*} must be passed explicitly as named keyword arguments (\texttt{metric="mse"}).
    \item \textbf{Var-Positional (\texttt{*args}):} Collects excess positional arguments into a \texttt{tuple}.
    \item \textbf{Var-Keyword (\texttt{**kwargs}):} Collects excess keyword arguments into a \texttt{dict}.
\end{itemize}

\subsection{Mathematical Closures}

\begin{definitionbox}{Formal Closure}
\index{Closure}
A \textbf{closure} is a record storing a function $f$ together with an environment: a mapping associating each free variable of $f$ (variables used locally but defined in an enclosing scope) with the value or reference to which the name was bound when the closure was created.
\begin{equation}
\mathcal{C} = \langle f, \{\text{var}_i \mapsto \text{binding}_i\} \rangle
\end{equation}
A closure retains access to its enclosing variables even after the outer enclosing function has completed execution and returned.
\end{definitionbox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Closures and Decorators in Machine Learning}
A decorator is a syntactic wrapper that transforms a function via a closure:
\begin{equation}
@\mathcal{D} \quad \text{def } f(\dots) \iff f = \mathcal{D}(f)
\end{equation}
Because decorators wrap target functions, they can inject automated logging, gradient clipping, timing profilers, or input shape verification without polluting the core mathematical algorithm.

\subsection{Stateful Estimator Factories}
Rather than instantiating an entire object-oriented class for a single learning rate decay, a closure can encapsulate continuous internal state using the \texttt{nonlocal} keyword:
\begin{lstlisting}[language=Python]
def make_decay_scheduler(initial_lr: float, decay_rate: float):
    lr = initial_lr
    def step():
        nonlocal lr
        current = lr
        lr *= (1.0 - decay_rate)
        return current
    return step
\end{lstlisting}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{The Mutable Default Argument Trap}
Default parameter expressions are evaluated \textbf{exactly once when the function definition is executed at module load time}, NOT upon each function call!
\begin{lstlisting}[language=Python]
def append_bias(features, bias=[1.0]):  # DANGEROUS!
    bias.append(0.5)
    return bias

print(append_bias([]))  # [1.0, 0.5]
print(append_bias([]))  # [1.0, 0.5, 0.5] -- PERSISTED MUTATION!
\end{lstlisting}
The default list object is shared across every single invocation.
\textbf{The Idiomatic Solution:} Use \texttt{None} as sentinel:
\begin{lstlisting}[language=Python]
def append_bias(features, bias=None):
    if bias is None:
        bias = [1.0]
    bias.append(0.5)
    return bias
\end{lstlisting}
\end{trapbox}

\begin{trapbox}{UnboundLocalError from Implicit Local Shadowing}
Referencing a global variable and assigning to it in the same function without declaring \texttt{global} causes an immediate crash:
\begin{lstlisting}[language=Python]
counter = 10
def update():
    print(counter)  # Raises UnboundLocalError!
    counter = 20
\end{lstlisting}
Because \texttt{counter = 20} appears in the body, the compiler marks \texttt{counter} as local to \texttt{update()}. The preceding \texttt{print} attempts to read the local variable before it was initialized! If mutating global state is required, declare \texttt{global counter}.
\end{trapbox}

\begin{trapbox}{Late Binding in Closures and Lambdas}
Functions created inside loops look up variables by name \textbf{at call time}, not at definition time:
\begin{lstlisting}[language=Python]
powers = [lambda x: x**i for i in range(3)]
print([p(2) for p in powers])  # Output: [4, 4, 4], NOT [1, 2, 4]!
\end{lstlisting}
When invoked, all three lambdas evaluate $i$ in their enclosing scope, where $i = 2$ upon loop termination!
\textbf{Correction via Default Parameter Binding:}
\begin{lstlisting}[language=Python]
powers = [lambda x, exp=i: x**exp for i in range(3)]  # Bound immediately!
\end{lstlisting}
\end{trapbox}

\begin{trapbox}{Order of Parameter Syntax Declarations}
Declaring parameters in illegal order raises a fatal \texttt{SyntaxError}:
\begin{lstlisting}[language=Python]
# SYNTAX ERROR: non-default argument follows default argument
def invalid_func(a=10, b): 
    pass
\end{lstlisting}
Parameters must strictly follow the declaration order:
\textbf{Positional-only $\to$ Standard positional $\to$ Default positional $\to$ \texttt{*args} $\to$ Keyword-only $\to$ Keyword defaults $\to$ \texttt{**kwargs}}.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following industrial script demonstrates a Decorator-Based Profiler, an Exponential Learning Rate Scheduler closure with \texttt{nonlocal} state, and an arbitrary-argument ML Loss Evaluator.

\begin{lstlisting}[language=Python]
import time
from typing import Callable, Any, Dict, List

def execution_profiler(func: Callable) -> Callable:
    """Decorator measuring execution latency and logging invocations."""
    def wrapper(*args, **kwargs) -> Any:
        start_time = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start_time
        print(f"[PROFILER] {func.__name__} executed in {elapsed:.6f}s")
        return result
    return wrapper

def create_adaptive_optimizer(initial_lr: float, decay_factor: float = 0.95):
    """
    Closure constructing a stateful optimizer schedule with persistent history.
    """
    current_lr = initial_lr
    iteration_step = 0
    history: List[float] = []

    def step(grad_norm: float) -> Dict[str, float]:
        nonlocal current_lr, iteration_step
        iteration_step += 1
        
        # Adaptive learning rate decay
        current_lr *= decay_factor
        effective_step = current_lr * grad_norm
        history.append(current_lr)

        return {
            "step": iteration_step,
            "learning_rate": round(current_lr, 6),
            "step_magnitude": round(effective_step, 6)
        }

    return step

@execution_profiler
def evaluate_loss_pipeline(
    predictions: List[float],
    targets: List[float],
    *,
    loss_type: str = "mse",
    sample_weights: List[float] = None
) -> float:
    """
    Computes weighted error metric enforcing keyword-only arguments.
    """
    n = len(predictions)
    if n != len(targets):
        raise ValueError("Predictions and targets dimension mismatch.")

    weights = sample_weights if sample_weights is not None else [1.0] * n

    if loss_type == "mse":
        total_loss = sum(w * (p - y)**2 for p, y, w in zip(predictions, targets, weights))
    elif loss_type == "mae":
        total_loss = sum(w * abs(p - y) for p, y, w in zip(predictions, targets, weights))
    else:
        raise ValueError(f"Unsupported loss_type: {loss_type}")

    return round(total_loss / sum(weights), 6)

# Execute components
optimizer = create_adaptive_optimizer(initial_lr=0.1, decay_factor=0.90)
for g in [1.5, 1.2, 0.8]:
    info = optimizer(g)
    print(f"Step {info['step']}: LR = {info['learning_rate']}, Magnitude = {info['step_magnitude']}")

preds = [2.5, 0.0, 2.1, 1.8]
actuals = [3.0, -0.5, 2.0, 1.5]
mse_loss = evaluate_loss_pipeline(preds, actuals, loss_type="mse")
print(f"Computed Loss: {mse_loss}")
# Output:
# Step 1: LR = 0.09, Magnitude = 0.135
# Step 2: LR = 0.081, Magnitude = 0.0972
# Step 3: LR = 0.0729, Magnitude = 0.05832
# [PROFILER] evaluate_loss_pipeline executed in 0.0000...s
# Computed Loss: 0.1475
\end{lstlisting}
