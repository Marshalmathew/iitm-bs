\chapter{NumPy Fundamentals, Memory Strides \& Vectorized Broadcasting}

Python's native dynamic lists provide extraordinary versatility but introduce prohibitive computational bottlenecks for numerical data science. Every element in a Python list is a heap-allocated \texttt{PyObject} pointer, inducing pointer-chasing latency and preventing CPU cache line exploitation. \index{NumPy}\textbf{NumPy} (Numerical Python) resolves this by introducing the \index{ndarray}\textbf{\texttt{ndarray}}: a contiguous, typed memory buffer executing at native C and Fortran speeds. Through \textbf{memory strides}, \textbf{SIMD vectorization}, and \index{Broadcasting}\textbf{Broadcasting Algebra}, NumPy serves as the computational engine powering TensorFlow, PyTorch, SciPy, and Pandas. Mastering the internal architecture of array strides, view-versus-copy mechanics, and multidimensional tensor manipulations is the hallmark of professional scientific computing.

\section{Mathematical \& Computational Foundations}

\subsection{The \texttt{ndarray} Memory Buffer and Strides Architecture}

\begin{definitionbox}{Memory Layout, Strides, and Shape}
\index{Memory Strides} \index{Contiguous Memory}
A NumPy array consists of a lightweight Python header descriptor pointing to a single contiguous block of raw binary data in memory. The structural layout is defined by three attributes:
\begin{enumerate}
    \item \textbf{Data Type (\texttt{dtype}):} Fixed homogeneous binary representation (e.g., \texttt{np.float64} consumes 8 bytes).
    \item \textbf{Shape (\texttt{shape}):} A tuple of integers $(d_0, d_1, \dots, d_{k-1})$ specifying dimensions.
    \item \textbf{Strides (\texttt{strides}):} A tuple of byte offsets $(s_0, s_1, \dots, s_{k-1})$ specifying the number of bytes to step in memory to advance by one index along each axis:
    \begin{equation}
    \text{Address}(A[i_0, i_1, \dots, i_{k-1}]) = \text{BaseAddress} + \sum_{j=0}^{k-1} i_j \times s_j
    \end{equation}
\end{enumerate}
In standard C-contiguous (row-major) order for a 2D matrix of shape $(M, N)$ and element size $B$ bytes:
\begin{equation}
s_0 = N \times B \text{ bytes}, \quad s_1 = B \text{ bytes}
\end{equation}
Transposing a matrix $A^T$ does not copy or move any data in memory; it simply swaps the strides and shape: \texttt{A.T.strides = (s1, s0)}.
\end{definitionbox}

\subsection{Vectorization and SIMD Acceleration}

\begin{theorembox}{Vectorized Instruction Throughput}
\index{Vectorization} \index{SIMD}
In pure Python, computing $\mathbf{c} = \mathbf{a} + \mathbf{b}$ for $10^6$ elements requires one million bytecode dispatches, dynamic type checks, and pointer dereferences.
In NumPy, \textbf{Vectorization} delegates the loop to compiled C code. Because elements are contiguous, modern CPU architectures utilize \textbf{SIMD (Single Instruction, Multiple Data)} vector registers (AVX-512, AVX2), executing 8 to 16 double-precision additions per CPU clock cycle. This typically yields a $50\times$ to $200\times$ speedup over interpreted Python loops.
\end{theorembox}

\subsection{The General Broadcasting Rules}

\begin{theorembox}{The Strict Broadcasting Invariant}
\index{Broadcasting Rules}
Broadcasting allows element-wise operations between arrays of different shapes without physically replicating data in memory.
When operating on two arrays $A$ and $B$, NumPy compares their shapes element-wise \textbf{from right to left (trailing dimensions first)}:
\begin{enumerate}
    \item If the arrays have different numbers of dimensions, the shape of the shorter array is padded with ones on the left.
    \item Two dimensions are \textbf{compatible} if and only if:
    \begin{equation}
    d_A == d_B \quad \lor \quad d_A == 1 \quad \lor \quad d_B == 1
    \end{equation}
    \item If compatible, the resulting dimension size is $\max(d_A, d_B)$. Along any axis of size $1$, NumPy sets the stride to $0$, logically stretching the array across that axis without memory allocation.
    \item If dimensions conflict and neither is $1$, a \texttt{ValueError: operands could not be broadcast together} is raised.
\end{enumerate}
\end{theorembox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Ordinary Least Squares (OLS) Normal Equations in NumPy}
In multiple linear regression, given feature matrix $X \in \mathbb{R}^{n \times d}$ and target vector $\mathbf{y} \in \mathbb{R}^n$, the closed-form weight vector minimizing residual sum of squares is given by the normal equations:
\begin{equation}
\hat{\mathbf{w}} = (X^T X)^{-1} X^T \mathbf{y}
\end{equation}
In NumPy, rather than computing the matrix inverse explicitly via \texttt{np.linalg.inv()} (which is computationally unstable and prone to precision loss), we solve the linear system directly:
\begin{lstlisting}[language=Python]
w_hat = np.linalg.solve(X.T @ X, X.T @ y)
\end{lstlisting}
This utilizes LAPACK LU/Cholesky factorization, computing solutions in $\mathcal{O}(d^3)$ time with optimal numerical conditioning.

\subsection{Views versus Copies: The Internal Buffer Base}
NumPy makes a strict distinction between creating a \textbf{View} (a new header pointing to the existing buffer) and a \textbf{Copy} (allocating a new buffer):
\begin{itemize}
    \item \textbf{Basic Slicing (\texttt{arr[1:5]}):} Always returns a view. Modifying the view modifies the original array! Check \texttt{view.base is arr}.
    \item \textbf{Advanced / Fancy Indexing (\texttt{arr[[0, 2]]} or \texttt{arr[arr > 0]}):} Always constructs an independent copy in memory.
\end{itemize}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{The In-Place Mutation of Basic Slices (View Trap)}
Modifying a basic slice alters the original parent array:
\begin{lstlisting}[language=Python]
import numpy as np
orig = np.array([10, 20, 30, 40])
sub = orig[1:3]  # Basic slice: VIEW!
sub[0] = 999
print(orig)  # Output: [ 10 999  30  40] -- Original was mutated!
\end{lstlisting}
If mutation isolation is required, explicitly create a copy: \texttt{sub = orig[1:3].copy()}.
\end{trapbox}

\begin{trapbox}{Boolean Chaining in NumPy: \texttt{and}/\texttt{or} vs \texttt{\&}/\texttt{|}}
Using Python's logical \texttt{and}/\texttt{or} keywords on NumPy arrays causes an immediate crash:
\begin{lstlisting}[language=Python]
arr = np.array([1, 5, 10])
# BUG: raises ValueError: The truth value of an array is ambiguous!
mask = (arr > 2) and (arr < 8)
\end{lstlisting}
Python's \texttt{and} requires a single scalar boolean. For element-wise boolean array operations, you must use bitwise operators with mandatory parentheses:
\begin{lstlisting}[language=Python]
mask = (arr > 2) & (arr < 8)  # Correct! Produces [False, True, False]
\end{lstlisting}
\end{trapbox}

\begin{trapbox}{Matrix Multiplication (\texttt{@}) vs Element-Wise Multiplication (\texttt{*})}
In NumPy, \texttt{A * B} performs Hadamard (element-wise) multiplication, requiring broadcast-compatible dimensions. Matrix multiplication ($C_{ij} = \sum_k A_{ik} B_{kj}$) requires the \texttt{@} operator or \texttt{np.matmul(A, B)}.
\end{trapbox}

\begin{trapbox}{Accumulating Operations: \texttt{arr = arr + 1} vs \texttt{arr += 1}}
\texttt{arr = arr + 1} allocates a brand new array on the heap and rebinds the name \texttt{arr}, leaving other references unchanged.
\texttt{arr += 1} performs an in-place mutation directly on the existing buffer, saving memory and updating all aliased views.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following industrial script implements a Vectorized Ridge Regression Estimator, computes the $R^2$ coefficient of determination, and calculates pairwise Euclidean distance matrices using broadcasting algebra.

\begin{lstlisting}[language=Python]
import numpy as np

def compute_pairwise_distances(X: np.ndarray, Y: np.ndarray) -> np.ndarray:
    """
    Computes Euclidean distance matrix between rows of X and Y using broadcasting.
    X: shape (M, D), Y: shape (N, D) -> Output: shape (M, N)
    ||x_i - y_j||^2 = ||x_i||^2 + ||y_j||^2 - 2 * <x_i, y_j>
    """
    # Reshape X to (M, 1, D) and Y to (1, N, D)
    diff = X[:, np.newaxis, :] - Y[np.newaxis, :, :]  # Shape: (M, N, D)
    return np.sqrt(np.sum(diff**2, axis=-1))

class VectorizedRidgeRegressor:
    """
    Vectorized Ridge Regression: w* = (X^T X + lambda * I)^(-1) X^T y
    """
    def __init__(self, alpha: float = 1.0):
        self.alpha = alpha
        self.weights_ = None

    def fit(self, X: np.ndarray, y: np.ndarray):
        # Prepend bias column of ones
        n_samples = X.shape[0]
        X_design = np.hstack([np.ones((n_samples, 1)), X])
        d_features = X_design.shape[1]

        # Regularization matrix (do not regularize bias)
        reg_matrix = self.alpha * np.eye(d_features)
        reg_matrix[0, 0] = 0.0

        # Solve normal equations via stable linear solve
        A = X_design.T @ X_design + reg_matrix
        b = X_design.T @ y
        self.weights_ = np.linalg.solve(A, b)
        return self

    def predict(self, X: np.ndarray) -> np.ndarray:
        n_samples = X.shape[0]
        X_design = np.hstack([np.ones((n_samples, 1)), X])
        return X_design @ self.weights_

    def score(self, X: np.ndarray, y: np.ndarray) -> float:
        """Computes R^2 coefficient of determination."""
        y_pred = self.predict(X)
        ss_res = np.sum((y - y_pred)**2)
        ss_tot = np.sum((y - np.mean(y))**2)
        return float(1.0 - (ss_res / ss_tot))

# Synthetic dataset generation
np.random.seed(42)
X_train = np.random.uniform(-5.0, 5.0, size=(100, 2))
# True relation: y = 3.5*x0 - 2.0*x1 + 4.0 + noise
y_train = 3.5 * X_train[:, 0] - 2.0 * X_train[:, 1] + 4.0 + np.random.normal(0, 0.5, size=100)

model = VectorizedRidgeRegressor(alpha=0.1).fit(X_train, y_train)
r2 = model.score(X_train, y_train)

print("Learned Weights (Bias, w0, w1):", np.round(model.weights_, 3))
print("Training R^2 Score:", round(r2, 4))

# Pairwise distance demonstration
points_A = np.array([[0.0, 0.0], [3.0, 4.0]])
points_B = np.array([[1.0, 1.0], [0.0, 3.0], [4.0, 0.0]])
dist_matrix = compute_pairwise_distances(points_A, points_B)
print("Pairwise Distances:\n", np.round(dist_matrix, 3))
# Output:
# Learned Weights: [4.019, 3.491, -2.008]
# Training R^2 Score: 0.9961
\end{lstlisting}
