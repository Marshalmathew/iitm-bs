\chapter{Introduction to Python, Variables, Data Types \& Operators}

Python is the undisputed computational lingua franca of modern Data Science, Machine Learning, and Artificial Intelligence. Behind its clean, expressive syntax lies a sophisticated runtime architecture: an interpreted, dynamically typed, yet \index{Strong Typing}\textbf{strongly typed} object model where all variables act as memory reference pointers rather than static storage boxes. Understanding how Python manages memory, binds variable names, handles arbitrary-precision integers, and evaluates operator precedence is the essential foundation for building reliable, high-performance machine learning pipelines.

\section{Mathematical \& Computational Foundations}

\subsection{The Python Execution and Object Memory Model}

\begin{definitionbox}{Variable Assignment as Name Binding (Reference Semantics)}
\index{Name Binding} \index{Reference Semantics}
In languages like C++ or Java, a variable is a named memory box of fixed size holding a raw value. In Python, \textbf{variables are names (tags) bound to heap-allocated objects}.
When executing:
\begin{lstlisting}[language=Python]
x = 10
\end{lstlisting}
Python performs three distinct steps:
\begin{enumerate}
    \item Allocates a full \texttt{PyObject} on the memory heap with fields: reference count (\texttt{ob\_refcnt}), type pointer (\texttt{ob\_type = int}), and payload value (\texttt{10}).
    \item Looks up the identifier \texttt{x} in the current namespace dictionary.
    \item Binds the name \texttt{x} to point to the memory address of the integer object.
\end{enumerate}
The built-in function \texttt{id(x)} returns the unique memory address of the referenced object.
\end{definitionbox}

\begin{theorembox}{Dynamic Typing versus Strong Typing}
Python is both \textbf{dynamically typed} and \textbf{strongly typed}:
\begin{itemize}
    \item \textbf{Dynamically Typed:} Types are associated with \textbf{objects in memory at runtime}, not with variable names. A name can point to an integer at one moment and be rebound to a string later:
    \begin{lstlisting}[language=Python]
    x = 42        # x points to int object
    x = "data"    # x now points to str object; no compile error
    \end{lstlisting}
    \item \textbf{Strongly Typed:} Object types are strictly enforced. Python will \textbf{never} implicitly coerce incompatible types during operations:
    \begin{lstlisting}[language=Python]
    result = "10" + 5  # Raises TypeError: can only concatenate str to str
    \end{lstlisting}
\end{itemize}
\end{theorembox}

\subsection{Core Primitive Data Types}

\begin{definitionbox}{Built-in Primitive Data Types}
\index{Primitive Data Types}
\begin{enumerate}
    \item \textbf{Integer (\texttt{int}):} In Python 3, integers have \textbf{arbitrary precision} (unbounded size). Python automatically allocates as many bytes as needed, eliminating integer overflow errors common in 32-bit and 64-bit compiled languages ($2^{1000}$ computes seamlessly).
    \item \textbf{Float (\texttt{float}):} Implemented as standard IEEE 754 double-precision 64-bit numbers (53 bits of precision, approximately 15--17 significant decimal digits).
    \item \textbf{String (\texttt{str}):} Immutable sequences of Unicode code points. Once constructed, individual characters cannot be modified in place.
    \item \textbf{Boolean (\texttt{bool}):} Subclass of \texttt{int} representing truth values: \texttt{True} (value 1) and \texttt{False} (value 0).
\end{enumerate}
\end{definitionbox}

\subsection{Arithmetic Operators and Modulo Mathematics}

\begin{theorembox}{The Fundamental Division-Modulo Invariant}
For any two numbers $a$ (dividend) and $b$ (divisor, $b \neq 0$), Python defines floor division \texttt{//} and modulus \texttt{\%} such that the algebraic invariant always holds:
\begin{equation}
b \times (a \mathbin{/\!\!/} b) + (a \mathbin{\%} b) = a
\end{equation}
Python uses \textbf{floor division} (rounding toward negative infinity $\lfloor a/b \rfloor$), NOT truncation toward zero.
Consequently:
\begin{equation}
17 \mathbin{/\!\!/} 5 = 3, \quad 17 \mathbin{\%} 5 = 2 \implies 5(3) + 2 = 17
\end{equation}
\begin{equation}
-17 \mathbin{/\!\!/} 5 = \lfloor -3.4 \rfloor = -4, \quad -17 \mathbin{\%} 5 = 3 \implies 5(-4) + 3 = -17
\end{equation}
The sign of $a \mathbin{\%} b$ always matches the sign of divisor $b$.
\end{theorembox}

\section{Deep Intuition \& Conceptual Derivations}

\subsection{Why Floating-Point Arithmetic Violates Exact Real Equality}

A frequent source of critical bugs in scientific computing is assuming that mathematical equalities hold exactly in binary floating-point representation.
\begin{theorembox}{Floating-Point Representation Imprecision (IEEE 754)}
In Python:
\begin{lstlisting}[language=Python]
print(0.1 + 0.2 == 0.3)  # Evaluates to False!
print(0.1 + 0.2)         # Evaluates to 0.30000000000000004
\end{lstlisting}
\end{theorembox}

\begin{proof}
Computers represent numbers in base-2 (binary). A rational fraction $\frac{p}{q}$ has a terminating representation in base $b$ if and only if all prime factors of $q$ divide $b$.
In base-10, the denominator $10 = 2 \times 5$, so fractions like $\frac{1}{10} = 0.1$ terminate cleanly.
However, in base-2, the only prime factor is $2$. Expanding $0.1 = \frac{1}{10}$ into binary gives an \textbf{infinitely repeating sequence}:
\begin{equation*}
(0.1)_{10} = (0.000110011001100110011\dots)_2
\end{equation*}
Because an IEEE 754 64-bit float allocates exactly 53 bits for the mantissa (significand), the repeating sequence must be rounded and truncated at the 53rd bit.
Consequently:
\begin{align*}
0.1 &\approx 0.1000000000000000055511151231257827021181583404541015625 \\
0.2 &\approx 0.200000000000000011102230246251565404236316680908203125 \\
0.1 + 0.2 &\approx 0.3000000000000000444089209850062616169452667236328125 \\
0.3 &\approx 0.299999999999999988897769753748434595763683319091796875
\end{align*}
Because $(0.1 + 0.2)$ has bits ending in \texttt{...04} while $0.3$ ends in \texttt{...98}, their bit patterns differ, causing \texttt{==} to return \texttt{False}.
In scientific computing, floating-point equality must \textbf{always} be evaluated using tolerance bounds:
\begin{equation}
|a - b| < \epsilon \quad \text{or} \quad \texttt{math.isclose(a, b, rel\_tol=1e-9)}
\end{equation}
\end{proof}

\subsection{String Slicing Mechanics and Memory Efficiency}

Python's string slice syntax \texttt{s[start:stop:step]} operates under clean closed-open interval algebra $[start, stop)$:
\begin{itemize}
    \item \textbf{Length Formula:} If $step = 1$, the length of the slice is strictly $\max(0, stop - start)$.
    \item \textbf{Graceful Boundary Clamping:} Unlike direct index access \texttt{s[k]} (which raises \texttt{IndexError} if $k \ge \text{len}(s)$), slicing automatically clamps out-of-range indices to the valid string boundaries:
    \begin{lstlisting}[language=Python]
    s = "data"
    print(s[0:100])  # Returns "data" with zero runtime error!
    \end{lstlisting}
    \item \textbf{Reversal Idiom:} When $step = -1$, setting \texttt{s[::-1]} sets default start to the last index and stop past the first index, reversing the sequence in $\mathcal{O}(n)$ time.
\end{itemize}

\section{Explicit Gotchas \& Diagnostic Misconceptions}

\begin{trapbox}{Trap 1: Floating-Point Equality Checks in Convergence Criteria}
In machine learning optimization, writing \texttt{while loss == 0.0:} or checking if gradient norm \texttt{norm == 0.0} creates an infinite loop due to floating-point truncation. Always evaluate convergence against a tolerance threshold: \texttt{while loss > 1e-6:}.
\end{trapbox}

\begin{trapbox}{Trap 2: Floor Division with Negative Numbers}
Students coming from C/C++/Java expect integer division to truncate toward zero: in C++, \texttt{-17 / 5} produces \texttt{-3}. In Python, \texttt{-17 // 5} yields \textbf{\texttt{-4}} because Python strictly floors toward negative infinity ($\lfloor -3.4 \rfloor = -4$). Furthermore, \texttt{-17 \% 5} yields \textbf{\texttt{3}} (since $5(-4) + 3 = -17$), NOT \texttt{-2}.
\end{trapbox}

\begin{trapbox}{Trap 3: Chained Comparisons vs. Bitwise / Logical Evaluation}
Python allows mathematical chained comparisons: \texttt{1 < x < 5} is evaluated internally as \texttt{(1 < x) and (x < 5)} with short-circuiting. However, writing \texttt{1 < x and x < 5} with bitwise operators (\texttt{1 < x \& x < 5}) breaks because bitwise \texttt{\&} has higher precedence than comparison operators, parsing as \texttt{1 < (x \& x) < 5}.
\end{trapbox}

\begin{trapbox}{Trap 4: Division in Python 3 Always Returns a Float}
In Python 2, \texttt{5 / 2} evaluated to \texttt{2} (integer division). In Python 3 (PEP 238), the single slash \texttt{/} operator \textbf{always} performs true float division: \texttt{10 / 2} returns \texttt{5.0} (type \texttt{float}), NOT \texttt{5} (type \texttt{int}). To obtain an integer result, you must explicitly use floor division \texttt{10 // 2}.
\end{trapbox}

\section{Python / Scientific Computing Lab}

The following self-contained scientific computing script demonstrates object identity tracking, arbitrary integer precision, IEEE 754 floating-point tolerance testing, and safe string slicing.

\begin{lstlisting}[language=Python, caption={Python Lab: Memory Identity, Float Tolerances, and Robust Slicing}]
import math
import sys

# 1. Object Identity and Memory Address Tracking
x = 1000
y = 1000
print(f"Value equality (x == y): {x == y}")
print(f"Object identity (x is y): {x is y}")
print(f"Memory address id(x): {hex(id(x))}, id(y): {hex(id(y))}")

# 2. Arbitrary Precision Integer Arithmetic (No 64-bit overflow)
huge_power = 2 ** 100
print(f"\n2^100 exact integer: {huge_power}")
print(f"Memory allocated for huge integer: {sys.getsizeof(huge_power)} bytes")

# 3. IEEE 754 Floating-Point Comparison & Math.isclose
a = 0.1 + 0.2
b = 0.3
print(f"\nRaw equality (0.1 + 0.2 == 0.3): {a == b}")
print(f"Float representation of 0.1 + 0.2: {a:.20f}")
print(f"Float representation of 0.3:       {b:.20f}")

# Proper scientific comparison
is_close = math.isclose(a, b, rel_tol=1e-9)
print(f"Scientific tolerance check (math.isclose): {is_close}")
assert is_close, "Precision check failed!"

# 4. Modulo and Floor Division Semantics with Negatives
div_pos = 17 // 5
mod_pos = 17 % 5
div_neg = -17 // 5
mod_neg = -17 % 5
print(f"\nPositive: 17 // 5 = {div_pos}, 17 % 5 = {mod_pos} --> 5*{div_pos} + {mod_pos} = {5*div_pos + mod_pos}")
print(f"Negative: -17 // 5 = {div_neg}, -17 % 5 = {mod_neg} --> 5*{div_neg} + {mod_neg} = {5*div_neg + mod_neg}")

# 5. String Slicing and Negative Stride
token = "DeepLearning"
print(f"\nOriginal Token: {token}")
print(f"Prefix [0:4]:   {token[0:4]}")
print(f"Suffix [-8:]:   {token[-8:]}")
print(f"Reversed [::-1]: {token[::-1]}")
print(f"Safe slice beyond bounds [0:100]: '{token[0:100]}'")
\end{lstlisting}
